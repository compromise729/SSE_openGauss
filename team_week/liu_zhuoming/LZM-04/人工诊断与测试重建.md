# LZM-04｜人工诊断与测试实例重建

## 一、保留现场并读取诊断

从 verify 输出取得 RUN_DIR，在外层 Linux root 终端使用真实路径。不要把示例变量提示文字当成值；把下面输入项填写为运行输出里的完整路径。

```bash
cd /opt/og/openGauss-server
source /home/omm/.sse_opengauss_env
source /opt/rh/rh-python36/enable
tools=/opt/og/openGauss-server/team_week/liu_zhuoming/LZM-04/preflight
read -r -p '输入本次 RUN_DIR 完整路径：' run
test -d "$run/db/instance"
test ! -e "$run/db/instance/postmaster.pid"
runuser -u omm -- /opt/og/openGauss-server/dest/bin/pg_controldata "$run/db/instance"
```

预期实例已停止，控制文件显示 shut down。若仍有运行 PID，先核对进程实际数据目录，不对其他实例执行停机命令。

读取某个故障目录，例如计数保存失败夹具：

```bash
state="$run/evidence/s04_counter"
runuser -u omm -- python3 "$tools/diagnose.py" --state "$state"
cat "$run/evidence/lzm04/results.json"
```

诊断只读取文件元信息、标记是否存在及非密钥状态摘要。私钥和 key_id 不输出字节或摘要。其他场景按 results.json 中 state_dir 选择目录，例如 s04_mapping、s04_legacy。operation_incomplete=true 表示未完成现场，不是允许恢复继续的信号。

## 二、如何判读

| 现场 | 应核对 |
| --- | --- |
| operation.v1 存在 | 结合请求 stderr 的最后阶段、数据库实际提交情况和原计数判断；不自动清标记。 |
| 计数保存失败 | 数据库可能已提交新索引，但本地仍是旧计数；禁止盲目重试。 |
| 进程强制退出 | 核对数据库是否回滚、文件标记是否保留；进程退出释放系统锁不代表操作完成。 |
| 映射保存失败 | 服务端表可能已经创建，本地版本登记可能部分保存；有标记的状态不可使用，不回退旧明文表。 |
| 旧重插失败对照 | 可能已经取出全部索引；保留业务表、原状态和错误日志，setup 不能恢复索引。 |
| 新版事务重插失败 | 当前事务回滚使索引恢复，但标记仍保守阻断；不能把自动删标记当成恢复。 |

诊断记录应包含实际代码版本、构建指纹、状态目录、数据库名、失败阶段和计数/数据库证据。不要打印私钥或上传整个 private 运行目录。

## 三、仅对可丢弃测试环境重新建立

本工具夹具只使用公开数据。需要重新测试时，保留旧运行目录，按 env.md 再执行 verify.sh；它创建新的个人目录、数据库和密钥。无需删除旧文件，也不把旧数据目录当作新目录。

```bash
read -r -p '输入已成功构建的 BUILD_DIR 完整路径：' build
test -x "$build/gaussdb" && test -x "$build/gsql"
bash "$tools/verify.sh" "$build"
```

这叫新建测试环境，不是恢复旧环境。真实业务环境的密钥恢复、跨端事务和索引重建需要专门方案；本任务不提供换钥、清计数、删除标记后继续业务的操作。
