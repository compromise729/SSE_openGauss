## 当前契约

采用 [SHY-02 v1.0](../../leader/SHY-02/接口与数据格式约定.md) 的表标记、函数签名、密文封装和作用域。首轮支持一个独立状态环境内的一张 `public` 新版逻辑表，以及以下 gsql 入口。

~~~sql
CREATE TABLE week_demo (ind text, keyword text SSE='FIDES', payload text)
WITH (sse_storage='ROW_AEAD_V1');
INSERT INTO week_demo VALUES ('1','apple','red apple'),('2','apple','green apple');
SELECT * FROM week_demo WHERE keyword='apple';
~~~

显式表选项开启新版建表。语句本身可以分行，业务字符串中的换行仍返回 `invalid_input`。新版表的投影、复合条件、连接、更新、删除以及超出限定语法的请求在客户端拒绝。普通系统目录和其他 schema 的普通表沿用原 SQL 路径。

每个关键词的**累计更新计数上限为 4096**，插入与搜索后的重插共同占用额度。插入按同一批次每个词的实际行数在状态锁内预检。已耗尽的词在建立操作标记前拒绝搜索。剩余额度不足以重插实际命中的唯一 rid 时，数据库回滚本次取出，客户端确认回滚后清除本次尚未修改计数的标记。该分支返回 `unsupported`，可以继续使用同一环境。

## 搜索及故障约定

1. 校验版本和状态。健康的未登记词返回零行。
2. 持锁读取最新计数并持久化操作标记，生成真实 Fides 搜索令牌。
3. 在同一数据库事务中取出索引，校验 UT，认证位置载荷并对 rid 去重，检查实际重插额度。
4. 生成更新令牌，重插密文位置，按 rid 回查业务密文。客户端认证并解密整批结果，验证结果集合。
5. 确认数据库提交，保存本地计数，清除操作标记。随后向 gsql 交付明文结果。

重插或回查失败会回滚该数据库事务并保留客户端操作标记。数据库提交后发生本地持久化故障时，标记继续阻断后续操作，供人工根据两侧证据诊断。跨端自动恢复以及服务端重启后的完整复验留在后续故障任务。

## 原生复验结果

在 CentOS 使用同一源码目录原生构建 `gaussdb`、`gsql` 与 `libpq`，用同一目录的 `SSE_v1.sql` 建立隔离实例。命令及产物路径见 [原生复跑步骤](env.md)。

`make -j6`、`make install` 和 `verify-all.sh` 均退出 0。**18 项模块用例和 18 项真实请求用例全部通过。** 原版在普通系统目录查询回归中报 `public schema required`，修复版通过同项检查。测试实例已停机。源码、工具、原生产物的 SHA-256 与各用例结论见 [原生复验结果](result/contract-native-results.json)。
