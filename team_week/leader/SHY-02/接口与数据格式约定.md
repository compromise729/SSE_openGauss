# SHY-02 接口与数据格式约定 v1.0

本契约从 SHY-01 的 25489f563f25b522d0cd37a6c85865039e3f340f 接续，LZM-01 的隔离环境与前置检查作为环境入口。施骅洋发布本轮实现约定，ZYC-01、YZH-01、LMD-01、LZM-02 据此开发，后续更改通过契约版本和交接记录同步。

## 1. 用户入口与范围

可信客户端支持下列入口。新版建表子句由张永昌在原 parser_create_table 改动映射之前识别与校验，再调用新版服务端建表函数。

```sql
CREATE TABLE week_demo (ind text, keyword text SSE='FIDES', payload text)
WITH (sse_storage='ROW_AEAD_V1');
INSERT INTO week_demo VALUES ('1','apple','red apple'),('2','apple','green apple'),('3','banana','yellow banana');
SELECT * FROM week_demo WHERE keyword='apple';
```

字段固定为 ind、keyword、payload，三项均为 UTF-8 文本。schema 固定 public，表名采用小写 ASCII 字母开头的 `[a-z][a-z0-9_]{0,39}`。第一轮只在每个独立状态环境中使用一张新版逻辑表。业务 ind 允许重复，记录身份使用客户端随机生成的 rid。

支持 ASCII 单引号字符串中的 SQL 标准双单引号转义，保持大小写、空格、中文和空串。张永昌须按引号状态提取 VALUES，避免按逗号或全文 AND 直接切分。NULL、美元引用、反斜杠转义字符串、参数化业务语句、投影、复合条件、UPDATE、DELETE、JOIN 等入口返回 unsupported。普通表走原有 SQL 路径。转义符之外的引号应明确报告输入错误。

每个业务字段最大 16384 UTF-8 字节，keyword 额外限制为 1024 字节，一批 1～100 行。SQL 文本输入拒绝 NUL、CR、LF，已有关键词计数格式靠逐行文本存储。序列化模块仍须通过尾零字节测试。超限、格式、版本、密钥等可预检错误全部在计数变化和网络发送前返回。

## 2. 标识和版本登记

rid 由 YZH-01 的 new_rid 使用密码学随机源生成 16 字节，以 32 个小写十六进制字符传输。数据表主键是完整 rid。索引位置恢复后交给新版字符串过滤器，ZYC-03 对重复的同一 rid 去重，操作标记为 0 才接受。当前版本接到其他操作值返回 protocol_invalid。

Scope 含 deployment_id、database_oid、schema、table。deployment_id 由 LZM-02 在显式初始化隔离状态时生成，原始 16 字节保存为 deployment.v1，Scope 中使用小写十六进制表示，database_oid 用同连接只读查询取得，schema/table 按建表规则确定。认证前 Scope 已知。它提供载荷用途与表绑定，SSE 计数仍使用当前实现的关键词字典，因此环境限制随交付说明记录。

本地 `row_aead_tables.v1` 每条记录按 TSV 保存 deployment_id、database_oid、schema、table、协议版本五项，文件头固定 `SSE_ROW_TABLES_V1`。原 sse_table.mat 保留原方案格式，两份映射必须一致。服务端 public.sse_v1_catalog 保存逻辑 schema、逻辑表、protocol_version。新版查询在发搜索请求前对照两端版本，缺项或冲突返回 state_invalid。

建表也写处理中标记。服务端建表与 catalog 登记同事务，返回成功后写本地新版登记与原表映射。其间失败保留标记，重启时报 incomplete_operation。表已存在不覆盖，返回 db_failed。自动重试前须人工检查已有对象与本地状态。

## 3. 密钥与随机化认证加密

统一使用当前工具链支持的 OpenSSL EVP AES-256-GCM。业务密钥 Krow 和位置密钥 Kloc 分别随机生成 32 字节，key_id 为随机 16 字节。每次加密由 RAND_bytes 生成新的 12 字节 nonce，并检查返回值。nonce 与密文同存，密钥保留在客户端。

initialize_keys 仅在显式创建全新状态目录时调用，使用独占创建和 0600 权限。文件为 row_aead_v1.key、locator_aead_v1.key、row_aead_v1.keyid，目录为 0700。load_keys 要求长度分别为 32、32、16，key_id 与封装不匹配返回 key_invalid。已有状态缺钥必须失败。KeySet 字节只在客户端使用，报告只显示文件职责和长度。

业务行明文采用三个连续的 `uint32_be 长度 + 原始字节`，顺序 ind、keyword、payload。解码逐项检查总长度，拒绝尾随字节和超限字段。三字段最大编码长度为 49164 字节。位置明文为 rid 的原始 16 字节加一个操作字节，共 17 字节，操作 0 表示插入。

封装统一为标准带填充的 Base64，编码内容如下。

|偏移|长度|内容|
|---|---|---|
|0|4|ASCII SSE1|
|4|1|版本 1|
|5|1|用途 1 为业务行，2 为位置|
|6|16|原始 key_id|
|22|12|nonce|
|34|4|大端密文字节长度|
|38|可变|GCM 密文，长度等于该类明文字节数|
|38+长度|16|GCM 标签|

头部 38 字节全部加入 AAD。AAD 后续拼接 Scope 的四项，每项使用 uint32_be 长度及 UTF-8 字节，deployment_id 用 32 字符十六进制表示。业务行 AAD 再追加 rid 原始 16 字节，位置 AAD 使用已知 Scope。封装的长度、版本、用途和 key_id 在分配输出前检查，认证成功后才返回解密内容。

业务封装字节数为明文长度加 54，Base64 长度为 `4 * ceil((明文长度+54)/3)`，范围 88～65624。位置封装固定为 71 字节，Base64 为 96 字符。数据库负责结构和长度检查，客户端负责认证。

所有输出参数进入接口和失败时清空，Status 与合法空字段分离。密码可用性小样位于 checks/crypto_probe.cpp，实际 YZH-01 模块按此契约实现 AAD、封装与密钥生命周期。

## 4. 物理表和数据库接口

public.<table>_data 保存 `rid text primary key, data_blob text not null`，public.<table>_index 保存 `ut text primary key, locator_blob text not null`。新版没有 join_col。字段读取必须使用明确列名。ut 沿用 Fides 生成规则，locator_blob 是本契约的位置封装。

李孟德在 sse_sql 中实现以下接口，SQL 参数使用 libpq 参数绑定，数组元素通过统一数组编码器构造，动态标识符逐项校验并 quote_ident。

|函数签名|返回与事务约定|
|---|---|
|sse_v1_create(schema_name text, logical_name text)|void，主表/索引/catalog 同事务创建|
|sse_v1_insert(schema_name text, logical_name text, rids text[], data_blobs text[], uts text[], locator_blobs text[])|void，四个非空等长数组，一批整体成功或整体回滚|
|sse_v1_reinsert(schema_name text, logical_name text, uts text[], locator_blobs text[])|void，只写索引，数组等长，可以为空|
|sse_v1_fetch(schema_name text, logical_name text, rids text[])|TABLE(rid text,data_blob text)，位置唯一且按明确列名返回|

Fides 搜索仍由现有 token、derivation_key、add_count 生成内部请求。李孟德为新版入口调整目标索引列，服务端返回 `ut,locator_blob`，不依赖返回顺序。张永昌验证返回 ut 属于本次请求及数量边界，然后对每条位置封装认证恢复 rid。使用原 Fides 令牌和状态推进方式，重插为每个有效 rid 生成更新令牌并写回认证位置载荷。

fetch 的返回集合必须与请求的唯一 rid 集合一致。缺行或多出/重复返回行报 inconsistent_result。空集合直接返回零行，不生成空 IN SQL。数据库约束或事务失败由 SQL ERROR 传播，客户端检查每轮 PGresult 状态。

sql/physical_schema_draft.sql 是可执行的物理形状夹具，使用公开合成载荷验证字段和约束，生产函数由 LMD-01 实现。本轮同会话执行 BEGIN、COMMIT 等普通 SQL 时，含新版写操作明确拒绝嵌入用户外层事务，以避免服务端提交时机与本地标记完成时机冲突。

## 5. 状态接口与调用顺序

LZM-01 的 isolated.sh 继续负责进程与目录隔离，当前只读检查器的 0/1/2/3 退出含义保留。LZM-02 以 include/sse_v1_contract.hpp 为 C++ 接口，负责锁、标记和状态读写。

状态接口的目录由 SSE_V1_STATE_DIR 指定，未设置时使用当前已隔离挂载的 /opt/og/openGauss-server/sse_storage。preflight 返回 Status、keyword_registered 和 counter。健康但未登记的词使用 ok + false，查询直接空集。状态文件损坏使用 state_invalid，已有登记词生成空 token 则报 protocol_invalid。命令行检查器仍可用退出码 1 表示未登记。

begin_operation 先取得目录互斥锁，再重新检查状态与版本，持久化 operation.v1 标记。标记记录协议版本、操作 id、Scope 和 create/insert/search 阶段，使用临时文件、fsync 和 rename。锁在完成或客户端退出前保持。阻断已有未完成标记，拒绝第二个客户端。

INSERT 的顺序为输入解析/长度检查、密钥加载、行与位置加密、preflight、begin_operation、再次核对状态、生成更新令牌并推进计数、数据库整批写入、状态持久化、complete_operation。任何步骤失败保存诊断和标记，停止该操作。全部预检完成后才开始有副作用流程。

SELECT 的顺序为解析/版本/密钥检查、preflight、健康未知词短路、begin_operation、令牌生成与搜索、认证位置/字符串过滤、生成新令牌/重插、按 rid 回查、认证全部业务行、验证结果集、状态保存、complete_operation、统一展示。每轮错误都停止后续请求。完成标记清除失败也返回错误，禁止打印已准备的明文结果。

状态保存先写临时文件，检查所有写入、刷新和关闭结果，再原子替换并持久化父目录。多个本地文件与数据库跨轮请求的恢复由未完成标记阻断，后续在人工诊断后处理。启动时先核对已有状态与密钥，再调用可能创建旧客户端对象的初始化代码，明确新建环境和恢复环境。

## 6. 错误与日志约定

Code 枚举见头文件。ok 是成功，unsupported/invalid_input 为发送前拒绝，unknown_keyword 仅供诊断兼容，正常查询对外呈现零行。state_invalid、key_invalid、protocol_invalid、auth_failed、db_failed、incomplete_operation、busy、inconsistent_result 均为操作失败。crypto_failed 覆盖随机源与密码库调用失败。

内部 SQL 执行应返回有效失败状态到 gsql，使用 ON_ERROR_STOP 的批处理返回非零。所有明文先在内存准备，整次业务操作全部通过后打印。常规日志只记任务 id、阶段、错误类别、rid/条数等必要诊断，公开夹具报告可记录指定原文，密钥始终不输出。
